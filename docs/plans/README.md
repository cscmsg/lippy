# Plans

Work briefs for things that do not exist yet. Each one is written before the
code, names the files it expects to touch, and records the decisions and traps
found while scoping it.

They are kept in the repository rather than in a private tracker so that the
reasoning behind a piece of work is readable alongside the work itself, and so
that a plan can be picked up without the person who wrote it.

A plan is not documentation. If it describes something that already ships, it
has outlived its purpose and belongs in the README instead.
